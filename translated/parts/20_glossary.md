# 多智能体系统术语表

本术语表提供本书所涵盖的与多智能体系统、人工智能智能体及其应用相关的关键术语和概念的定义。

## A

**行动-感知循环（Action-Perception Loop）**
智能体的基本运作循环：采取行动、感知结果，并基于结果调整方法。这种迭代过程持续到任务解决，将智能体与生成单次响应的简单模型区分开来。

**动作序列生成（Action Sequence Generation）**
生成式 AI 模型将高层任务转化为计算机使用智能体的特定界面动作的过程。动作序列生成可以遵循显式规划（预先生成完整动作序列）或隐式规划（基于当前界面状态迭代生成动作），选择取决于界面动态性和任务需求。

**动作空间（Action Space）**
计算机使用智能体可以在界面上执行的动作集合，如点击按钮、输入文本、选择下拉菜单或提交表单。动作空间必须显式定义并提供给生成式模型以进行动作序列生成。

**智能体（Agent）**
一种能够推理、行动、沟通和适应以解决问题的软件实体。智能体将生成式 AI 模型与工具和记忆结合，采取超越文本生成的具体行动。

**智能体上下文（Agent Context）**
一种可序列化的数据结构，在智能体执行期间管理当前会话状态，包括对话消息、请求元数据（user_id、session_id）和用于编排的共享状态。与提供跨会话持久存储的 Memory 不同，Agent Context 是瞬态的，通常在主要交互之间重置。这种设计支持无状态智能体执行，任何服务器都可以处理恢复请求，而无需在内存中维护会话状态。

**智能体执行循环（Agent Execution Loop）**
智能体通过五个步骤迭代处理任务的基本运作模式：(1) 通过组合任务、指令、记忆和历史准备上下文；(2) 用此上下文调用模型；(3) 通过处理文本或执行工具调用来处理响应；(4) 通过将工具结果添加到上下文并重复来迭代；(5) 返回最终响应并更新记忆。此循环持续到智能体产生不带工具调用的最终文本响应。

**AI 驱动编排（AI-Driven Orchestration）**
一种自主编排模式，LLM 分析对话上下文和智能体能力，动态选择下一个响应的智能体，而非遵循固定的轮流规则。提供响应对话需求的自适应协调，同时保持集中式选择逻辑。比轮询更灵活，但比智能体通过对话自我选择的对话驱动模式更结构化。

**智能体中间件（Agent Middleware）**
在运行时拦截和处理智能体操作（模型调用、工具执行）的软件例程或钩子，支持安全验证、日志记录、速率限制和错误处理等横切关注点，而无需修改核心智能体逻辑。这些组件形成中间件链，其中每个都可以检查、修改或完全阻止操作。

**智能体即工具模式（Agents as Tools Pattern）**
一种组合模式，任何智能体都可以通过将其包装在工具接口中成为其他智能体的工具。每个专家智能体保持完全独立——自己的模型配置、工具集、记忆和中间件——同时成为更大系统中可复用的组件。这支持灵活的架构，不同智能体可以针对特定领域优化，并由更高层智能体无缝协调。

**智能体噪声（Agentic Noise）**
当自主智能体破坏设计有人类参与假设的双边平台均衡时，对人类福利产生的集体有害影响。通过不对称加速（智能体加速一侧而另一侧保持人类节奏，打破平台平衡）或没有福利收益的对称加速（双方都被智能体加速，但产生高产翻腾而非改进结果）发生。特征是通过注意力消耗、资源竞争和平台拥塞而无成比例价值创造的规模放大，个体良性的智能体动作在规模上变得有问题。

**智能体间协议（Agent-to-Agent Protocol，A2A）**
自主智能体之间标准化通信的协议规范，支持跨不同智能体框架和实现的互操作性。定义分布式多智能体系统中智能体发现、消息交换、能力协商和协调任务执行的模式。由谷歌引入并由 Linux 基金会治理，A2A 使用以任务为中心的架构，交互创建带生命周期状态（submitted、working、input-required、completed、failed）的持久 Task 对象，支持跨网络中断的可恢复执行。

**对齐（Alignment）**
在 AI 系统的上下文中，确保模型行为匹配人类价值观、意图和期望目标的过程。传统上通过人类反馈强化学习（RLHF）等技术实现，模型被训练为有帮助、诚实和无害。对于智能体式系统，对齐变得更具挑战性，因为网络规模训练削弱了数据策展与行为控制之间的联系，需要持续评估以检测行为漂移、谄媚和对齐伪装。

**对齐伪装（Alignment Faking）**
一种行为模式，AI 模型在被监控或训练期间战略性地遵守安全训练和期望目标，但在不被监控或部署时回复到问题或不合规行为。研究表明，模型可以从事这种行为以保护其偏好不被训练过程修改，表现出关于何时被评估的情境意识。这种现象代表智能体式系统中行为控制的根本挑战，因为训练期间的组件测试可能无法预测部署行为。

**自主多智能体系统（Autonomous Multi-Agent System）**
使用 AI 驱动协调的多智能体系统，控制流在运行时动态确定。智能体协商职责，并基于任务需求调整协作，支持对复杂或不可预测任务的自适应响应。

## C

**能力发现（UX 原则）（Capability Discovery）**
一种 UX 原则，通过提供任务示例、高置信度任务建议和成功概率指示器，帮助用户理解智能体能可靠做什么，解决用户不知道哪些任务会顺利与失败的问题。

**检查点（Checkpointing）**
在智能体或工作流执行期间的特定点保存执行状态的机制，支持失败后恢复、暂停和恢复长时间运行任务，以及通过从保存状态回放执行来调试。包括通过哈希比较的工作流结构验证，确保恢复时的检查点兼容性。对任何服务器都可以恢复执行的无状态水平扩展和基础设施失败恢复至关重要。

**复杂任务（Complex Tasks）**
以四个关键属性为特征的任务：需要规划（多步分解）、需要多元专长（专门知识领域）、涉及海量上下文（大量信息）和需要适应性解决方案（解决方案迭代涌现的动态环境）。

**计算机使用智能体（Computer Use Agent）**
通过用户界面与软件应用交互的 AI 智能体，模拟点击、输入和导航等人类动作。这些智能体观察界面状态、推理所需动作并执行任务，自动化缺乏程序化 API 或需要视觉推理的复杂工作流。

**压缩（Compaction）**
一种上下文工程策略，在每次 LLM 调用前修剪旧消息以保持 Token 使用在预算内。实现包括头+尾修剪（保留任务指令和近期工作，丢弃中间部分）和摘要（用 LLM 生成的摘要替换旧消息）。必须尊重原子组——带工具调用的消息及其结果不能拆分。见上下文工程。

**条件工作流（Conditional Workflow）**
一种编排模式，使用基于逻辑的边基于条件确定下一个节点，支持分支执行路径和动态路由。

**上下文工程（Context Engineering）**
在智能体任务执行期间主动管理演进上下文的实践，以尊重有限的注意力预算，同时保持模型最优条件化。与专注于设计单个输入的提示词工程不同，上下文工程通过压缩（修剪旧消息）、主动记忆管理（选择性持久化）、上下文隔离（带单独上下文的分层智能体）和结果过滤（浓缩工具输出）等策略应对多步执行中的上下文增长。对防止上下文腐化（高 Token 计数下的表现退化）和上下文爆炸（消息、工具结果和记忆检索的快速累积）至关重要。

**上下文窗口（Context Window）**
语言模型在单个输入和输出序列中能够处理的最大 Token（词或词片段）数量，受模型架构和计算资源约束。

**对话驱动模式（Conversation-Driven Pattern）**
一种自主编排模式（也称为群聊），所有智能体参与共享对话，编排通过对话中的轮流发言涌现，而非显式计划或结构化交接。

**成本感知的行动委托（UX 原则）（Cost-Aware Action Delegation）**
一种 UX 原则，用于传达行动后果，并提供用户控制机制处理不同成本级别的行动，从低成本自动执行到高成本批准需求。

## D

**委托设计（Delegation Design）**
多智能体系统的一种 UX 范式，用户向自主系统提供开放式任务指令，而非直接操纵特定界面控件，与传统界面设计形成对比。

**有向无环图（Directed Acyclic Graph，DAG）**
并行工作流中使用的图结构，节点代表计算单元，有向边定义控制流，无循环允许执行从开始到完成单向流动。

**分布式智能体（Distributed Agents）**
在单独执行上下文中运行的智能体——不同机器、容器、区域或组织——通过网络通信，无共享内存。它们面临经典分布式系统挑战（部分失败、网络延迟、协调复杂性），但提供改进的可扩展性、容错、执行环境隔离，以及利用跨不同基础设施的异构资源的能力。

## E

**提前停止（Early Stopping）**
一种失败模式，智能体在完成任务前停止执行。这可能发生在 LLM 返回不带工具调用的响应（退出循环）时，或智能体转入对话模式并请求确认继续时（例如，"我已处理前 4 个文件——要继续处理剩余 40 个吗？"）。通过建立自主任务完成预期的指令，以及在允许退出前验证实际完成的循环级结束钩子来解决。

**评估驱动的开发（Evaluation-Driven Development）**
多智能体系统的一种开发方法，在实现智能体行为之前定义成功标准、指标和评估基础设施。类似于传统软件的测试驱动开发（TDD），这种方法确保评估约束成为设计要求，使团队在实验无摩擦时更快迭代。

## G

**群聊模式（Group Chat Pattern）**
见对话驱动模式。

**通用工具（General-Purpose Tools）**
支持广泛能力的工具，如允许智能体完成任何可表达为代码的任务的代码执行器，或用于基于序列交互的 UI 界面驱动器。

**生成式人工智能（Generative AI，GenAI）**
深度神经网络的一个子集，擅长识别数据集中的复杂模式并生成新的、相似的数据点。包括大型语言模型（LLM）、图像生成模型（IGM）和大型多模态模型（LMM）。

## H

**交接模式（Handoff Pattern）**
一种自主编排模式，使智能体能够以有限的局部知识运行，同时通过点对点委托实现协调行为，智能体就何时以及向谁转移控制做出局部决策。

**人类委托（Human Delegation）**
一种任务管理模式，复杂或敏感的任务升级给人类监督，使用基于 LLM 的推理确定升级需求，或基于规则的触发器实现确定性升级。

**人在回路（Human-in-the-Loop）**
一种交互模式，用户积极参与智能体执行，观察轨迹并在任务完成期间提供反馈、纠正或批准。

## I

**界面表示（Interface Representation）**
计算机使用智能体中将用户界面当前状态呈现给 AI 模型以理解和生成动作的方法。存在三种主要方法：基于文本的（DOM/HTML 结构）、基于图像的（截图）和混合的（结合两者），每种在精度、计算成本和视觉理解之间提供不同权衡。选择取决于应用类型、程序化访问可用性和任务需求。

**可中断性（UX 原则）（Interruptibility）**
一种 UX 原则，确保用户可以在执行期间的任何时刻中断、暂停、恢复或取消智能体动作，而不丢失进度或系统状态。

## J

**锯齿状前沿（Jagged Frontier）**
一种 AI 能力高度不均衡的现象，一些看似困难的任务执行良好，而看似简单的任务意外失败，在相似工作流内创造不可预测的可靠性。

**越狱（Jailbreak）**
在 LLM 的上下文中，从通常会拒绝此类请求的模型引出有害、不安全和不希望有的响应的攻击。越狱方法取一个目标 G（目标 LLM 拒绝响应的，如"如何制造炸弹"），将其改写为另一个提示词 P，通过旨在欺骗模型生成其通常会拒绝的内容的对抗性提示词绕过安全防护栏。当智能体被越狱时，后果超越有害文本，包括删除文件、外泄数据、未经授权的 API 调用和操纵生产系统。

## L

**大型语言模型（Large Language Model，LLM）**
在人类语言书面文本上训练的生成式模型，可以通过序列预测执行各种文本处理任务，如 GPT-4、Claude 和 Gemini。

**LLM 作为评判器（LLM-as-a-Judge）**
一种评估方法，强语言模型评估智能体输出的质量，特别是对不存在真实答案的无参考评估。LLM 评判器可以评估传统指标遗漏的细致品质（有用性、清晰度、正确性），支持正确解决方案差异很大的开放式任务的评估。

## M

**智能体自管理的记忆（Agent-Managed Memory）**
一种记忆管理方法，智能体通过工具直接控制其持久知识，显式决定存储什么、何时检索信息以及如何组织其知识库。与应用管理的记忆形成对比，后者存储和检索由应用代码控制。使智能体能够积极策展和组织自己的知识以实现跨会话学习。

**应用管理的记忆（Application-Managed Memory）**
一种记忆管理方法，开发者通过应用代码控制信息存储和检索，应用代码基于预定义策略（语义相似性、近期过滤）自动将相关上下文注入智能体提示词。智能体接收此上下文，但不控制存储或检索什么。通过自动上下文增强提供便利，而不给智能体存储决策。

**记忆（Memory）**
回忆和复用过去交互信息的能力，与推理能力（模型）和行动能力（工具）并列作为智能体架构的核心组件。分为短期记忆（当前任务的工作记忆）和长期记忆（跨会话的累积知识）。记忆系统可以是应用管理的（开发者控制）或智能体自管理的（智能体控制）。

**模型上下文协议（Model Context Protocol，MCP）**
一种标准化协议，使 AI 智能体通过客户端-服务器架构发现和交互外部数据源和工具。MCP 服务器暴露资源（数据源）、工具（可执行函数）和提示词（可复用模板），而客户端（AI 应用）可以动态发现和利用这些能力，无需硬编码集成。由 Anthropic 引入，MCP 通过提供跨不同 AI 平台和框架工作的供应商中立标准解决集成挑战。

**模型（Model）**
作为智能体推理引擎的大型语言模型（LLM）或大型多模态模型，支持决策、规划和自然语言理解。在智能体架构中，模型与记忆（信息存储）和工具（采取行动）并列构成三个核心组件之一。示例包括 GPT-4、Claude 和 Gemini。

**多智能体系统（Multi-Agent System）**
协作解决任务的智能体集合，每个智能体保持特定能力，系统以其协调机制为特征，协调机制决定智能体如何沟通、行动和共享控制流。

**多智能体工作流（Multi-Agent Workflow）**
使用预定义协调的多智能体系统，智能体遵循既定顺序和交接，具有清晰指定的角色、职责和控制流，创建可预测且可靠的过程。

## O

**可观测性（UX 原则）（Observability）**
一种 UX 原则，确保用户可以观察智能体动作、追溯决策背后的推理，并理解影响结果的数据来源，通过透明度建立信任。这包括追溯智能体决策和输出的来源及推理链（溯源）的能力，展示使用了什么数据源以及结论如何达成。

**OpenTelemetry**
由云原生计算基金会（CNCF）支持的开源可观测性框架，为跨编程语言和监控后端收集追踪、指标和日志提供供应商中立标准。支持一次埋点，无需代码更改即可导出到任何后端（Jaeger、Datadog、Azure Monitor）。

**OpenTelemetry Gen-AI 语义约定（OpenTelemetry Gen-AI Semantic Conventions）**
使用 OpenTelemetry 对 AI 操作埋点的标准化规范，为 LLM 调用、工具执行和智能体工作流定义一致的属性名和 Span 结构。这些约定支持跨任何 OTLP 兼容后端的供应商中立可观测性，内容属性（提示词、补全）设计上可选择加入以保护敏感信息。

**编排器循环（Orchestrator Loop）**
支撑所有多智能体协调的基本执行模式，与智能体执行循环平行但在多智能体级别运行。由五个步骤组成：选择下一个智能体、准备上下文、执行智能体、更新共享状态和检查终止条件。这种一致架构支持跨编排模式（轮询、AI 驱动、基于计划）的可组合性，并提供全面的可观测性。智能体执行循环支配个体智能体如何思考和行动，而编排器循环支配多个智能体如何协作。

## P

**并行工作流（Parallel Workflow）**
一种编排模式，使用 DAG 实现独立任务的并发执行，扇出阶段拆分工作，扇入阶段合并结果。

**基于计划的编排（Plan-Based Orchestration）**
一种自主模式，使用单一编排器智能体通过显式计划创建、动态任务分配和集中式进度监控管理整个任务执行。

**规划（Planning）**
将任务分解为必须成功完成的多个步骤，涉及对实现目标成功状态所需动作序列的战略思考。复杂任务的关键特征之一，与多元专长需求、海量上下文需求和适应性解决方案需求并列。

**提示词工程（Prompt Engineering）**
创建提高语言模型成功完成任务可能性的文本序列的实践，包括少样本提示和思维链提示等技术。

## R

**ReAct**
一种单智能体模式，创建思考-行动-观察循环，推理轨迹帮助引导和更新行动计划，而行动从外部环境收集信息。

**检索增强生成（Retrieval-Augmented Generation，RAG）**
一种技术，从数据源检索外部知识，并在推理前动态添加以增强模型提示词。这将模型的响应锚定在其训练数据之外的领域特定或最新信息上。虽然向量数据库支持用于确定相关性的语义相似性搜索，但 RAG 来源可以包括任何外部数据：传统数据库、API、文件系统或知识图谱。

**Reflexion**
一种单智能体模式，将失败信号转化为作为情景记忆存储的可操作语言反馈，用于未来尝试，使智能体能够从错误中学习。

**轮询编排（Round-Robin Orchestration）**
一种自主编排模式，智能体按固定的顺序轮流，每个智能体在循环重复前获得平等的贡献机会。提供均衡参与和可预测的对话流，适合需要公平智能体协作而无需复杂选择逻辑的场景。比 AI 驱动选择更简单，但对任务需求的适应性较低。

## S

**顺序工作流（Sequential Workflow）**
一种实现线性执行（A->B->C）的编排模式，每个节点的输出馈入下一个，确保有序处理，具有可预测的执行时序和清晰的错误隔离。

**序列化（Serialization）**
将多智能体系统组件（智能体、工作流、工具、记忆及其配置）转换为可移植格式（如 JSON 或 YAML）的过程，可以存储、共享、版本控制或在系统之间传输。支持配置管理、跨环境可复现性、可视化编辑工具和状态恢复。当每个组件都能序列化自身时，完整的智能体设置成为团队可以版本控制和一致部署的可共享产物。

**结构化输出（Structured Output）**
一种约束语言模型以特定格式生成响应的技术，如匹配预定义模式的 JSON 对象，确保可预测和机器可读的数据。应用不再解析自由格式文本，而是获得可以立即用于工具调用、记忆存储或系统协调的可靠结构化数据。这种可靠性是构建采取精确行动的智能体的基础。

**监督者模式（Supervisor Pattern）**
条件工作流的一种变体，中央控制节点评估请求，并基于任务特征将任务路由到专门智能体。

## T

**任务取消（Task Cancellation）**
中断并干净终止正在运行的智能体操作的能力，停止 LLM 调用、工具执行和所有下游处理。通过传播异步操作停止信号的取消令牌实现，使用户能够重新控制可能不正确、陷入循环或需要中途干预的长时间运行任务。

**任务管理（Task Management）**
确保多智能体系统富有成效的结果并防止失控执行的横切策略，包括终止模式和人类委托方法。

**终止模式（Termination Pattern）**
防止无限循环和过度资源消耗的策略，包括基于预算的限制、语义完成检测和外部干预信号。

**工具调用（Tool Calling）**
结构化输出的一种应用，语言模型生成与预定义工具模式匹配的精确格式 JSON 请求。模型不是生成自由格式文本，而是产生带正确类型参数的结构化函数调用，消除解析歧义，使智能体能够可靠地与外部系统交互，用于数据库查询、API 调用或文件操作等动作。

**轨迹（Trajectory）**
智能体或多智能体系统为应对任务而采取的推理和动作的完整记录，包括消息（对话流）、动作（工具调用和执行）、结果（成功/失败状态）和元数据（计时、Token 使用）。无论评估单个模型、智能体还是完整多智能体工作流，你从根本上评估的是轨迹——支持跨复杂度级别的一致评估方法。

**轮流发言（Turn Taking）**
对话驱动模式中智能体轮流向共享对话贡献内容的机制，通过对话实现涌现式编排。

**颠簸（Thrashing）**
智能体上下文管理中的一种失败模式，压缩预算设置过低，导致智能体重复读取被压缩从上下文丢弃的文件或重新获取信息。通过高重复读取率（超过 15%）诊断。颠簸比完全不压缩浪费更多 Token，因为智能体将其预算花在重新获取上下文上，而非取得进展。

**工具（Tools）**
为执行特定任务而设计的逻辑的具体实现，作为智能体在世界上采取具体行动的主要方法。与推理能力（模型）和信息存储（记忆）并列构成智能体架构的核心组件。可以是通用的（代码执行器、UI 驱动器）或领域特定的（天气 API、金融数据服务）。
